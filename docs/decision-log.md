# 判断ログ

## 2026-05-24: Google SitesだけでなくPWA化する

理由:

- Google Sitesは編集権限や引き継ぎで迷いやすい。
- メンバーの日常利用はスマートフォン中心になる。
- PWAならホーム画面追加、下部ナビ、検索、オフライン表示を作れる。

方針:

- PWAを日常利用の入口にする。
- Google Sitesは4月AI例会アーカイブや長い説明の保管先として残す。
- Google Drive/Sheetsは資料や出欠の実体として使う。

## 2026-05-24: 静的PWAから始める

理由:

- 引き継ぎしやすい。
- 認証やサーバー管理が不要。
- 年度更新はデータファイルの差し替えで対応できる。

今後:

- 担当者がブラウザ上で更新したい場合は、Google Sheetsをリンク管理元にする。
- 将来、ログインや管理画面が必要になった場合は、VercelやFirebase Hostingを検討する。

## 2026-05-24: 認証情報は掲載しない

理由:

- メンバー向けであっても、PWAやGoogle Sitesにログイン情報を置くのは危険。
- 引き継ぎ時に意図せず公開範囲が変わる可能性がある。

方針:

- アジェンダシステムなどはリンクだけ掲載する。
- ログイン情報が必要な場合は、別の安全な共有方法を使う。

## 2026-05-25: 引き継ぎ資料名を正規化する

理由:

- 引き継ぎ資料の入口が複数あると、次年度担当者がどれを見ればよいか迷うため。
- 自動化エージェントや開発者が一般的に認識しやすい標準名へ寄せるため。

方針:

- 標準名として `AGENTS.md` と `Design.md` を置く。
- 旧指定名の別ファイルは置かず、正規の入口を一つにする。

## 2026-05-25: GitHub Pagesで公開する

理由:

- 静的PWAとしてシンプルに公開できる。
- 更新履歴をGitで残せる。
- 引き継ぎ時にファイル一式と変更履歴を渡しやすい。

公開URL:

```text
https://gyawa24.github.io/chitose-jc-member-portal/
```

注意:

- GitHub Pagesで公開した内容はインターネット上から閲覧できる。
- 実ファイルの閲覧権限はGoogle Drive/Sheets側で管理する。
- 認証情報や個人情報はPWAにもリポジトリにも置かない。
